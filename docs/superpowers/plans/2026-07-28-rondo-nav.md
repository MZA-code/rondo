# Rondo — Plan d'implémentation : navigation et suivi de trace

> **Pour les agents :** SOUS-COMPÉTENCE REQUISE — utiliser `superpowers:subagent-driven-development`
> (recommandé) ou `superpowers:executing-plans` pour dérouler ce plan tâche par tâche.
> Les étapes utilisent la syntaxe case à cocher (`- [ ]`).

**Objectif :** suivre une trace GPX chargée à l'avance — flèche de direction, écart à la
trace, distance au prochain point, fil d'Ariane du parcours — sans fond de carte.

**Architecture :** le GNSS alimente des canaux comme n'importe quel autre capteur. Toute la
géodésie, l'analyse NMEA, la lecture GPX, la simplification de trace et le suivi sont du
C++ pur testé sur PC. La couche cible se réduit à un pilote de liaison série et à un
téléversement de fichier.

**Pile technique :** C++17, ESP-IDF 5.2+ (UART, LittleFS), LVGL 9, CMake, Catch2 v3.

## Contraintes globales

- **Aucun fond de carte.** Décision arrêtée dès la conception : ni tuiles raster, ni
  vectoriel, ni routage. On affiche une flèche, un écart et des distances.
- **Les positions sont des entiers en 1 × 10⁻⁷ degré**, jamais des flottants. C'est le
  format natif des récepteurs u-blox, il tient sur 4 octets, et il donne une résolution de
  1,1 cm sans perte de précision — là où un `float` sature à 7 chiffres significatifs,
  soit environ 1 m sous nos latitudes.
- **Le GNSS ne fournit jamais la vitesse affichée.** Il sert de recoupement et d'horloge.
  La vitesse vient du capteur à effet Hall, qui reste juste sous le couvert forestier.
- **La recherche du point le plus proche est locale**, dans une fenêtre autour du dernier
  index. Une recherche globale ferait sauter la navigation d'un bout à l'autre d'une trace
  qui se recoupe — ce qui arrive à toutes les boucles.
- **Aucune allocation dynamique dans `core/`.** La trace est un tableau de taille fixe.
- **C++17**, `-Wall -Wextra -Wpedantic -Werror` hors code tiers.
- Identifiants et messages de commit en **anglais**, commentaires et tests en **français**.
- **Prérequis :** `rondo-core`, `rondo-ui`, `rondo-acquisition` et `rondo-config` terminés
  (155 tests).

`core/geo.h` :

```cpp
#pragma once

#include <cstdint>

namespace rondo {

// Position en 1e-7 degre, format natif des recepteurs u-blox.
// Resolution 1,1 cm, 8 octets par point. Un float saturerait a environ
// 1 m de resolution sous nos latitudes : il n'est pas utilisable ici.
struct GeoPoint {
    int32_t lat_e7 = 0;
    int32_t lon_e7 = 0;
};

// Toutes ces fonctions utilisent une projection equirectangulaire locale.
// L'erreur reste sous 0,1 % en dessous de 100 km, ce qui est trois ordres
// de grandeur sous la precision utile pour suivre une trace de trail.
// Elles evitent la trigonometrie spherique complete, trop couteuse a 10 Hz
// sur un ESP32.

float distanceMetres(GeoPoint a, GeoPoint b);

// Cap de `from` vers `to`, de 0 a 360 degres, 0 = nord.
float bearingDegrees(GeoPoint from, GeoPoint to);

// Ecart lateral de `p` a la droite passant par `a` et `b`.
// POSITIF si `p` est a DROITE du cap a->b, negatif a gauche.
// Renvoie 0 si le segment est de longueur nulle.
float crossTrackMetres(GeoPoint p, GeoPoint a, GeoPoint b);

// Angle a corriger pour passer de `heading_deg` a `target_deg`,
// ramene dans -180..+180. Positif = tourner a droite.
float relativeBearing(float heading_deg, float target_deg);

}  // namespace rondo
```

`core/geo.cpp` :

```cpp
#include "core/geo.h"

#include <cmath>

namespace rondo {
namespace {

constexpr double kEarthRadiusM = 6371000.0;
constexpr double kPi = 3.14159265358979323846;
constexpr double kDegToRad = kPi / 180.0;
constexpr double kE7 = 1e-7;

struct LocalMetres {
    double east = 0.0;
    double north = 0.0;
};

// Projette `p` dans un repere metrique local centre sur `origin`.
LocalMetres toLocal(GeoPoint origin, GeoPoint p) {
    const double mean_lat_rad =
        (static_cast<double>(origin.lat_e7) + static_cast<double>(p.lat_e7)) * 0.5 * kE7 *
        kDegToRad;
    const double dlat_deg = (static_cast<double>(p.lat_e7) - origin.lat_e7) * kE7;
    const double dlon_deg = (static_cast<double>(p.lon_e7) - origin.lon_e7) * kE7;
    return {dlon_deg * kDegToRad * kEarthRadiusM * std::cos(mean_lat_rad),
            dlat_deg * kDegToRad * kEarthRadiusM};
}

}  // namespace

float distanceMetres(GeoPoint a, GeoPoint b) {
    const LocalMetres d = toLocal(a, b);
    return static_cast<float>(std::sqrt(d.east * d.east + d.north * d.north));
}

float bearingDegrees(GeoPoint from, GeoPoint to) {
    const LocalMetres d = toLocal(from, to);
    double deg = std::atan2(d.east, d.north) / kDegToRad;
    if (deg < 0.0) {
        deg += 360.0;
    }
    return static_cast<float>(deg);
}

float crossTrackMetres(GeoPoint p, GeoPoint a, GeoPoint b) {
    const LocalMetres ab = toLocal(a, b);
    const LocalMetres ap = toLocal(a, p);
    const double length = std::sqrt(ab.east * ab.east + ab.north * ab.north);
    if (length < 0.001) {
        return 0.0f;
    }
    // Produit vectoriel dans le repere (est, nord) : positif quand `p` est
    // a gauche du cap a->b. On inverse le signe pour que positif = droite,
    // qui est la convention attendue par l'interface.
    const double cross = ab.east * ap.north - ab.north * ap.east;
    return static_cast<float>(-cross / length);
}

float relativeBearing(float heading_deg, float target_deg) {
    float delta = target_deg - heading_deg;
    while (delta > 180.0f) {
        delta -= 360.0f;
    }
    while (delta < -180.0f) {
        delta += 360.0f;
    }
    return delta;
}

}  // namespace rondo
```

```cpp
#pragma once

#include <cstdint>

#include "core/geo.h"

namespace rondo {

struct NmeaFix {
    bool valid = false;        // renseigne par RMC
    GeoPoint position;
    float speed_kmh = 0.0f;
    float heading_deg = 0.0f;
    uint8_t satellites = 0;    // renseigne par GGA
    uint8_t fix_quality = 0;   // 0 = aucun, 1 = GPS, 2 = differentiel
};

// Verifie la somme de controle XOR entre '$' et '*'.
// Une phrase sans '$', sans '*' ou trop courte est refusee.
bool nmeaChecksumValid(const char* sentence);

// Traite une phrase complete et met a jour `fix`.
// Renvoie false si la somme est fausse ou si le type n'est pas reconnu ;
// dans ce cas `fix` n'est PAS modifie, hormis le drapeau `valid` qu'une
// phrase RMC invalide remet a false.
bool parseNmeaSentence(const char* sentence, NmeaFix& fix);

}  // namespace rondo
```

`core/nmea.cpp` — points à respecter :

- Conversion latitude et longitude : le format NMEA est `DDMM.mmmm`, **pas** des degrés
  décimaux. Séparer les degrés des minutes, puis `degres + minutes / 60`, et multiplier par
  10⁷. Appliquer le signe selon `S` ou `W`. C'est l'erreur classique sur ce format : lire
  `4807.038` comme 48,07 degrés donne une position fausse de 8 km.
- Vitesse : le champ RMC est en **nœuds**, multiplier par 1,852.
- Aucun `atof` sur un champ vide : un champ absent laisse la valeur précédente inchangée.
- Comparer le type de phrase sur les **trois derniers caractères** du talker (`RMC`, `GGA`),
  pour accepter tous les préfixes de constellation.
- Ne jamais écrire dans la chaîne d'entrée : elle peut venir d'un tampon partagé.

```cpp
#pragma once

#include <cstddef>

#include "core/geo.h"

namespace rondo {

// Trace a suivre, chargee depuis un fichier GPX.
//
// Taille fixe : 2000 points a 8 octets font 16 Kio, ce qui tient sans
// PSRAM. Un GPX de telephone en contient souvent plus de 10 000 : la
// lecture DECIME au fil de l'eau plutot que de refuser le fichier.
class Track {
 public:
    static constexpr size_t kMaxPoints = 2000;

    // Analyse ciblee des balises <trkpt lat="..." lon="...">.
    // Ce n'est pas un analyseur XML complet, et ce n'est pas necessaire :
    // le GPX est un format assez regulier pour cela, et embarquer un
    // analyseur XML sur la cible serait disproportionne.
    //
    // Renvoie false si aucun point valide n'est trouve. Le contenu
    // precedent est remplace dans tous les cas.
    bool loadFromGpx(const char* xml, size_t len);

    void clear();

    size_t size() const { return count_; }
    GeoPoint at(size_t index) const;
    float totalLengthMetres() const;

    GeoPoint* mutablePoints() { return points_; }
    void setSize(size_t count);

 private:
    void append(GeoPoint p);
    void decimate();

    GeoPoint points_[kMaxPoints] = {};
    size_t count_ = 0;
    size_t stride_ = 1;   // pas de decimation courant
    size_t seen_ = 0;     // points rencontres depuis le dernier doublement
};

}  // namespace rondo
```

`core/track.cpp` — `append()` applique la décimation :

```cpp
void Track::append(GeoPoint p) {
    if (seen_ % stride_ != 0) {
        ++seen_;
        return;
    }
    ++seen_;

    if (count_ == kMaxPoints) {
        decimate();
    }
    points_[count_++] = p;
}

// Ne garde qu'un point sur deux et double le pas. Le premier point est
// toujours conserve : c'est le depart de la trace.
void Track::decimate() {
    size_t kept = 0;
    for (size_t i = 0; i < count_; i += 2) {
        points_[kept++] = points_[i];
    }
    count_ = kept;
    stride_ *= 2;
    seen_ = 0;
}
```

La conversion `lat="45.0100000"` vers `int32_t` en 1 × 10⁻⁷ degré doit se faire **sans
passer par un `float`** : lire la partie entière, puis jusqu'à sept décimales, et composer
l'entier. Un `float` intermédiaire perdrait les deux derniers chiffres.

- [ ] **Étape 3 : écrire le suivi**

`core/track_follower.h` :

```cpp
#pragma once

#include <cstddef>

#include "core/geo.h"
#include "core/track.h"

namespace rondo {

struct NavState {
    bool on_track = false;
    float cross_track_m = 0.0f;        // positif a droite de la trace
    float bearing_deg = 0.0f;          // cap a suivre
    float distance_to_next_m = 0.0f;
    float distance_remaining_m = 0.0f;
    size_t nearest_index = 0;
};

// Suit une trace chargee : ecart lateral, cap a suivre, distances.
//
// La recherche du segment le plus proche est LOCALE, dans une fenetre
// autour du dernier index. Sur une boucle qui se recoupe, une recherche
// globale ferait basculer la navigation a l'autre bout du parcours des
// qu'on repasse pres d'un point deja visite.
class TrackFollower {
 public:
    TrackFollower(const Track& track, float off_track_threshold_m, size_t search_window);

    NavState update(GeoPoint position);

    // A appeler au chargement d'une nouvelle trace ou apres une reprise
    // de fix : la recherche locale repart alors du debut.
    void reset();

 private:
    const Track& track_;
    float off_track_threshold_m_;
    size_t search_window_;
    size_t current_index_ = 0;
};

}  // namespace rondo
```

`core/track_follower.cpp` — `update()` :

1. Si la trace a moins de deux points, renvoyer un `NavState` par défaut.
2. Chercher, entre `current_index_` et `current_index_ + search_window_` (borné à la fin de
   la trace), le segment dont le point le plus proche minimise la distance.
3. Retenir cet index dans `current_index_`. **Il ne recule jamais** : on suit une trace dans
   un sens.
4. `cross_track_m` = `crossTrackMetres(position, at(i), at(i + 1))`.
5. `bearing_deg` = `bearingDegrees(position, at(i + 1))`.
6. `distance_to_next_m` = `distanceMetres(position, at(i + 1))`.
7. `distance_remaining_m` = `distance_to_next_m` plus la somme des longueurs des segments
   restants. Pré-calculer ces sommes cumulées au premier appel plutôt qu'à chaque mise à
   jour : à 2000 points et 10 Hz, la différence est réelle.
8. `on_track` = `std::fabs(cross_track_m) <= off_track_threshold_m_`.

Ajouter `track_follower.cpp` aux sources de `rondo_core` et le test à `rondo_tests`.

|---|---|

astronomique, les thèmes chargeables depuis un fichier, et l'application mobile compagnon.

en trail ne réclame pas.

**Les évolutions les plus probables**, dans l'ordre où elles apporteraient le plus :
un fournisseur de régime moteur par captation sur le fil de bougie (déjà prévu au schéma),
une jauge d'essence si une sonde est installée, et des profils communautaires pour d'autres
modèles — qui ne demandent aucun code, seulement un fichier JSON dans `profiles/`.
